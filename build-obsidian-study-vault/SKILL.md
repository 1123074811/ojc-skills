# 构建 Obsidian 学科知识库

把资料转换、知识建模、图谱构建和完整性验收作为一条流水线。完成标准不是“转换进程结束”，而是每份唯一资料均有记录、正文经过清理、知识点有实质内容、链接可解析、层级可达，并通过原资料回查。

## 硬约束

- 优先使用文件系统、CLI、API 和后台进程。除非用户明确要求，否则不控制桌面、鼠标、键盘或 Obsidian 窗口。
- 保留原始资料和已有 `.canvas`；只在明确确认后删除原件或不可恢复内容。
- 在独立暂存区处理转换产物，验收后再合入知识库。
- 不把“PDF 数量”“Markdown 数量”或 MinerU 成功退出当作完整性证明。
- 不使用未核对上下文的全局替换。删除噪声前先证明它是广告、页眉页脚、水印或无学术意义的重复内容。
- 不用空白叶子、伪造链接或无意义中心链接美化图谱。

## 工作流

### 1. 建立基线

1. 读取仓库约束、README、现有目录和 Git 状态。
2. 递归盘点 PDF、DOCX、PPT/PPTX、图片、Markdown、附件和 Canvas。
3. 对原始文件计算 SHA-256，区分“物理文件数”和“唯一内容数”；记录完全重复文件，不重复转换。
4. 建立资料清单，至少记录原路径、格式、哈希、页数或幻灯片数、重复组、转换状态、输出路径、复核状态和异常。
5. 检查已有转换结果，优先续做和修复，不从头覆盖已验证成果。

### 2. 选择并运行转换器

- 数学公式、复杂排版、扫描 PDF：优先 MinerU 或具备版面分析能力的 OCR。
- 可复制文本的简单 PDF：可使用更轻量的文本提取工具，但必须验证公式、表格和阅读顺序。
- DOCX、PPTX：优先原生结构解析；仅在版式无法保留时渲染后 OCR。
- 图片：使用 OCR，并保留原图与页码映射。

先读取当前安装版本的 `--help` 和官方文档，再构造命令；MinerU 的 CLI、模型和后端参数会随版本变化。按批次执行，保存日志，支持中断续跑。不要为已成功且哈希未变化的源文件重复转换。

每批完成后立即检查：

- 输出文件存在且非空；
- 页数或页面标记没有明显断层；
- 公式、表格、图片路径可解析；
- 文本没有大面积乱码、倒序或缺页。

### 3. 去噪而不伤正文

先读取 [references/vault-schema.md](references/vault-schema.md) 的去噪分级，再处理：

1. 统计跨页、跨文件高频重复行和重复图片。
2. 建立项目级噪声词表，覆盖公众号、群号、免费分享、引流语、版权水印、页眉页脚和二维码说明。
3. 对确定性广告做批量清理；对可能属于课程说明或例题条件的内容逐项复核。
4. 删除 Markdown 中的广告图片引用后，只删除确认无学术内容且不再被引用的派生图片；不删除原始资料。
5. 清理空段落、连续分隔符、OCR 页码碎片和重复标题。
6. 再次搜索全部噪声词和可疑图片引用，保留零残留证据。

### 4. 规范 Markdown

- 使用 UTF-8、稳定标题层级、相对附件路径和 Obsidian Wikilink。
- 统一行内公式 `$...$`、块公式 `$$...$$`，修复常见 OCR 括号和上下标错误。
- 保留有信息量的定理、定义、证明、推导、例题、表格和插图。
- 一个规范文件名只对应一个图谱节点。发现同名知识点时，用学科或章节限定文件名，并用 `aliases` 保留自然名称。
- 将来源页码或原讲义位置写入笔记，确保内容可回查。

### 5. 建模知识层级

按实际课程结构选择层级，不机械增加“上册/下册”等中间层：

```text
知识库根节点
└── 学科或模块
    ├── 可选分册/单元
    └── 章节
        └── 具体知识点
```

规则：

- 根节点必须是实际 Markdown 文件，不只存在于 Canvas 或设想中。
- 父节点正文必须链接直接子节点；子节点必须回链直接父节点。
- 分册仅在原课程确有稳定分册且能改善导航时保留。
- 章节与知识点使用课程语义名称，禁止把讲义广告标题或文件批次名当作正式节点名。
- 叶子必须是具体知识点，并包含实质内容；不得只放标题或空模板。
- 只有确有概念依赖时才添加横向链接，避免为了图形聚集制造虚假关系。

笔记字段、目录和模板见 [references/vault-schema.md](references/vault-schema.md)。

### 6. 丰富知识点

从讲义正文中拆出粒度稳定的知识点。每个知识点至少覆盖适用项：

- 定义或问题背景；
- 成立条件；
- 核心结论、公式或算法；
- 推导、证明思路或直观理解；
- 典型题型或实际用法；
- 常见错误、易混点和边界条件；
- 前置、后续与相近知识点；
- 来源讲义与页码。

不要凭常识压缩掉讲义中的特有方法、例题结论或限制条件。需要补充通用知识时，明确区分“资料原文整理”和“补充说明”。

### 7. 配置 Obsidian 原生图谱

以真实 Wikilink 作为图谱边，原生全局关系图作为主入口：

- 根 → 学科 → 章节 → 知识点形成可遍历主干；
- 用路径、标签或 `level` 设计低饱和度颜色组；
- 调低链接距离、适度提高链接强度，以改善父子聚集；
- 保留已有 Canvas，可新增局部 Canvas 或局部图谱作为补充，不用它们替代全局图谱。

提前说明原生限制：全局图谱是力导向布局，不能保证严格树形位置；原生节点大小主要取决于链接度，不能可靠按自定义级别设置。不要通过虚假链接篡改语义来强行放大节点。更具体的图谱策略见 [references/vault-schema.md](references/vault-schema.md)。

### 8. 对照原资料复核

按唯一内容而非文件名逐份复核：

1. 对照目录、章节标题和页面范围，确认没有整章、整节或连续页缺失。
2. 对照定义、定理、公式、表格、图示和例题，确认没有因去噪误删。
3. 对每份资料建立“来源 → 输出笔记”的可追踪关系。
4. 对抽取异常、低 OCR 置信度、公式密集页和跨页表格做重点人工语义复核。
5. 对重复资料标记 `duplicate_of`，不要把未重复转换误报为遗漏。

只有在所有唯一资料均为“已覆盖”或有明确异常说明时，才报告转换完成。

### 9. 自动验收

运行：

```powershell
python scripts/audit_vault.py --vault <知识库目录> --source-root <原始资料目录> --root-note <根节点文件名>
```

按项目追加噪声模式：

```powershell
python scripts/audit_vault.py --vault <知识库目录> --noise-pattern "公众号名" --noise-pattern "群号"
```

脚本只读检查 Markdown、Wikilink、附件、重复标题、噪声、知识点空壳、根节点可达性和唯一源资料覆盖。再按 [references/acceptance-checklist.md](references/acceptance-checklist.md) 完成人工语义门禁。

### 10. Git 交付

1. 检查 `git diff`，排除原始大文件、模型缓存、临时渲染和日志，除非用户明确要求纳入。
2. 运行技能审计、仓库既有测试和 `git diff --check`。
3. 更新知识库 README，写清入口、目录、图谱使用方式、资料覆盖和已知限制。
4. 仅提交本次范围内改动，使用能概括成果的提交信息。
5. 用户要求推送时，确认远程与分支后推送，再核验远程提交 SHA。

## 完成报告

简洁报告：

- 物理资料数、唯一资料数和重复数；
- 已转换、已去噪、已关联的数量；
- 知识点数、失效链接数、噪声残留数、空壳知识点数；
- 根节点可达情况与图谱原生限制；
- 提交 SHA、远程分支以及未解决异常。

若仍有未复核页面、公式识别疑点或来源未覆盖，明确写出，不使用“全部完成”。
