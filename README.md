# 🧰 OJC-Skills

个人定制的 AI Agent 技能仓库。每个技能以 `SKILL.md` 为核心定义，Agent 加载后就知道"先做什么、怎么做、做到什么程度算完"。

> 🎯 技能不是通用 prompt，而是**绑定具体场景的结构化工作流**。

---

## 📦 技能总览

| 技能 | 定位 | 亮点 |
|------|------|------|
| 🧪 **lab-report** | 实验报告自动化 | 模板解析 + 格式固化 + 降 AIGC 改写 |
| 🧹 **windows-c-drive-cleanup** | C 盘空间管理 | 审计优先 + Junction 迁移 + 环境变量联动 |

| 📝 **xiaoxueqi-report-docx** | 小学期实训报告 | 章节结构 + 题注编号 + 占位符清理 |

## 🧪 lab-report — 实验报告自动化

> ✨ 把散落在脑子里的格式规范固化为可重复执行的脚本链，跑一遍就是一份合格报告。

### 💡 为什么做成技能

实验报告格式要求琐碎且容易遗漏 —— 宋体 / Times New Roman 混排、题注编号随章节递增、表格字号与正文不同…… 这个技能把 `format-rules.md` 和 `aigc-prompts.md` 中的规范直接烧进工作流，杜绝格式遗漏。

### 🎯 核心能力

**📄 文档操作**
- 🔍 解析 DOCX 模板，提取报告名称、章节结构、表格插入位置
- 📝 自动填写封面（学号 / 姓名 / 班级 / 日期），不触碰模板原有格式
- 📊 按规范插入测试用例表格，图表题注自动编号
- 💾 输出文件自动命名为 `<姓名>-<班级>-<学号>-<实验报告名>.docx`

**🤖 降 AIGC 率改写**
- 📚 内置专用提示词集：动词短语扩展、系统性词汇替换、"分-总-分" 结构
- 🔌 支持外部 API 调用 + 本地提示词双模式
- 🔒 技术术语、代码片段、文件名保持不变

**📎 附加功能**
- 📑 DOCX 表格批量导出为 Excel
- 📄 PDF 合并 / 拆分 / 文本提取

### 🏗️ 设计思路

实验报告是典型的**流水线型任务** —— 从模板到成品报告需要经过多个独立步骤，每步逻辑不同但必须串联执行：

```
模板分析 → 封面填写 → 内容生成 → 表格插入 → 题注管理 → 格式统一 → AIGC 改写 → 最终校验
```

因此技能将工作流拆分为一条 Python 脚本链，Agent 按顺序调用，每步完成一个明确的子任务。格式规范和降 AIGC 提示词作为独立参考文件维护，规范变更时只需改参考文件，不用动代码。

## 🧹 windows-c-drive-cleanup — C 盘空间管理

> 🛡️ 安全优先的 C 盘审计与迁移工具 —— 先只读扫描、报告给人类看、同意后才动手。

### 💡 为什么做成技能

C 盘清理最怕两件事：删错东西和迁完软件不能用。技能把"哪些能碰、哪些不能碰"写成白名单（`safe-targets.md`），把迁移路径和环境变量对应关系写成映射表（`migration-map.md`），Agent 不会凭直觉乱删。

### 🔄 四阶段工作流

```
🔍 审计 ──▶ 📋 报告 ──▶ ✅ 用户确认 ──▶ ⚡ 执行 ──▶ ✅ 验收
```

| 阶段 | 做什么 | 约束 |
|------|--------|------|
| 🔍 **审计** | 容量总览、目录画像、大文件扫描 | 只读，不改动 |
| 🧹 **清理** | 临时文件 / 包管理缓存 / 编辑器缓存 | 必须确认清单后 `-Execute` |
| 📦 **迁移** | robocopy → 备份 → Junction → 配环境变量 | 必须确认源、目标、影响后 `-Execute` |
| ✅ **验收** | 联接状态 + 环境变量 + 冒烟测试 | — |

### 🌟 设计亮点

- 🔗 **Junction 透明迁移** — `mklink /J` 让数据物理上在 D 盘，逻辑路径不变，软件零感知
- 👀 **预演模式** — 所有脚本默认只预览不执行，显式传 `-Execute` 才真正操作
- 📋 **迁移清单内置** — Gradle / Maven / npm / pip / Docker / Android SDK 等，每个标注配套环境变量
- 🔒 **验收闭环** — 迁移后自动检查 Junction 状态 + 环境变量 + 关键命令可用性

### 🏗️ 设计思路

系统管理是**交互式决策任务** —— 重点不在自动化脚本的数量，而在决策逻辑和安全性约束。4 个 PowerShell 脚本对应 4 个阶段，每个脚本内部通过参数（如 `-Execute`、`-ApprovedPath`）控制是否真正执行。Agent 的核心工作是根据参考文件中的白名单和映射表做出正确判断，而非盲目执行。

## 🔄 ai-development-workflow — 软件开发全流程

> 🧠 纯规范驱动的技能，一套六阶段决策框架，让 Agent 在复杂项目中不会"做到一半就停"或"做完不验证"。

```
建立意图 → 项目基线 → 适度计划 → 垂直切片实现 → 验证修复 → 安全交付
```

**关键约束**：
- 🛑 **讨论边界** — "只讨论 / 不要实现" 是硬边界，讨论阶段不编辑任何文件
- 🔒 **范围锚定** — "继续" 锚定最新未完成计划，不会自作主张扩大范围
- 🔍 **交付自检** — 交付前必须自检：最低置信度假设、最大遗漏、三个月后的故障模式

### 🏗️ 设计思路

软件开发是**开放式决策任务** —— 每个项目的技术栈、需求、约束都不同，无法用固定脚本覆盖。因此技能完全不依赖脚本，而是将决策框架和约束条件写入 SKILL.md，Agent 靠推理能力在每个具体场景中做出正确判断。参考文件（交付检查清单、开发者偏好画像）提供上下文补充，而非执行指令。

## 📐 技能架构

每个技能由三层组成：

| 层次 | 文件 | 作用 |
|------|------|------|
| 📄 **定义** | `SKILL.md` | YAML 元数据 + Markdown 工作流规范 |
| 📚 **参考** | `references/` | 规范文档、提示词模板、配置快照 |
| ⚙️ **脚本** | `scripts/` | 自动化脚本（Python / PowerShell）|

> 💡 脚本是**可选的执行工具**，数量由任务性质决定：流水线型任务需要多步串联（如 lab-report），交互式任务只需少量控制脚本（如 windows-c-drive-cleanup），纯决策型任务则完全不需要（如 ai-development-workflow）。

### 📁 目录结构

```
ojc-skills/
├── 🧪 lab-report/                    # 实验报告自动化（Python 脚本链）
│   ├── references/                   # 格式规范 + 降 AIGC 提示词
│   ├── scripts/                      # 10+ 个 Python 脚本
│   └── SKILL.md
├── 🧹 windows-c-drive-cleanup/       # C 盘空间管理（PowerShell 脚本）
│   ├── references/                   # 清理白名单 + 迁移映射 + 本机配置
│   ├── scripts/                      # 4 个 PowerShell 脚本
│   └── SKILL.md
├── 🔄 ai-development-workflow/       # 软件开发全流程（纯规范驱动）
│   ├── agents/                       # Agent 配置
│   ├── references/                   # 交付清单 + 开发者画像
│   └── SKILL.md
├── *.skill                           # 技能安装包
└── .gitignore
```

根目录的 `.skill` 文件是打包后的安装文件，用于将技能部署到 Agent 的技能目录。

---

## 🚀 快速开始

1️⃣ 将 `.skill` 文件安装到 Agent（Qoder / Claude Code 等）的技能目录

2️⃣ 在对话中触发技能（如 `$lab-report`）或用自然语言描述任务

3️⃣ Agent 读取 `SKILL.md`，按定义的工作流自主执行
